# Настройка Firebase для онлайна

Для игры нужна только **Firebase Realtime Database**. Firebase Auth, Firestore и
файлы `google-services.json` здесь не используются: клиент обращается к базе по
обычному HTTPS REST.

## Создание базы

1. Создай проект в [Firebase Console](https://console.firebase.google.com/).
2. Открой **Build → Realtime Database → Create Database**.
3. По возможности выбери ближайший к игрокам регион.
4. На вкладке **Rules** вставь содержимое `firebase.rules.json` и нажми
   **Publish**.

Актуальные правила выглядят так:

```json
{
  "rules": {
    ".read": false,
    ".write": false,
    "users": {
      ".read": true,
      "$nick": {
        ".write": "!data.exists() || newData.child('pass').val() == data.child('pass').val()"
      }
    },
    "rooms": {
      "$room": {
        "players": {
          ".read": true,
          "$slot": {
            ".write": true,
            ".validate": "$slot.matches(/^[0-3]$/)"
          }
        },
        "chat": {
          ".read": true,
          ".write": true,
          ".indexOn": ".key"
        }
      }
    },
    "event": {
      ".read": true,
      ".write": true
    }
  }
}
```

В Firebase Auth входить не надо. Ник и пароль проверяются клиентом и узлом
`users`, а сессия сохраняется в `auth.dat`. Эти правила открывают игровые слоты,
чат и чтение таблицы аккаунтов всем, кто знает адрес базы; для небольшой
тестовой игры это удобно, но для публичного сервера лучше добавить нормальную
серверную авторизацию и проверку данных.

## URL базы

Адрес находится сверху на вкладке **Data**. Он выглядит примерно так:

```text
https://project-name-default-rtdb.europe-west1.firebasedatabase.app
```

Укажи его без `.json` и без завершающего `/` в `game/config.ds`:

```dimscript
str FIREBASE="https://project-name-default-rtdb.europe-west1.firebasedatabase.app", ROOM="main"
```

После изменения пересобери игру.

## Что лежит в базе

```text
event/   номер ивента: 0 — нет, 1 — «диско», 2 — снегопад (в корне базы)
users/
  <ник>/ nick, pass, cups, candies, cls, azum, santa, level, levels
rooms/
  main/
    players/
      0/ uid, nick, x, y, angle, hp, alive, seq,
         px, py, pdx, pdy, punch, cls,
         frz, gift, gx, gy, gdx, gdy
      1/ ...
    chat/
      <ключ>/ uid, nick, text
```

- `x`, `y`, `angle`, `hp`, `alive` — состояние игрока;
- `seq` обновляется вместе с состоянием и помогает заметить зависший слот;
- `px`, `py`, `pdx`, `pdy` — точка и направление последнего удара;
- `punch` — растущий номер удара;
- `frz` — сколько секунд игрок ещё заморожен (соперники рисуют ледяную рамку);
- `gift` — растущий номер броска суператаки Деда Мороза, `gx`, `gy`, `gdx`,
  `gdy` — точка броска и направление. Соперник повторяет полёт подарка у себя и
  сам применяет к себе урон и заморозку, поэтому эффект одинаков у всех;
- `level` — выбранный уровень, `levels` — максимальный открытый уровень.
  Новый аккаунт начинает с уровня 0; первый уровень покупается за 30 кубков,
  каждый следующий — на 10 кубков дороже.

Правило для `users/$nick` разрешает создание только пустого узла. Существующую
запись можно менять только с тем же паролем, поэтому сохранение прогресса не
перезаписывает аккаунт другим паролем.

Узел `event` — это ивент, он лежит прямо в корне базы (не внутри комнаты) и
хранит номер:

- `0` или узла нет — ивента нет;
- `1` — «диско»: экран мигает и переливается цветами;
- `2` — «снегопад»: над ареной падает снег.

Ивенты запускаются прямо из игры: у аккаунтов со статусом администратора в
лобби появляется кнопка **«Админ»** с панелью команд, и строки «Ивент „Диско“»,
«Ивент „Снегопад“» и «Остановить ивент» пишут в этот узел. Клиент читает узел
отдельно от боя, раз в полсекунды, поэтому он не мешает движению. Чтобы ивент
заработал, не забудь опубликовать правила из `firebase.rules.json` (там открыт
доступ к `event`).

В выборе режима есть переключатель **«Эпилептикам (без мигания)»** — он
выключает мигание диско у конкретного игрока, чтобы люди с фотосенсорной
эпилепсией не ослепли, пока остальные танцуют.

У удара больше нет краткого поля `active`. Раньше оно успевало вернуться в ноль
между двумя запросами, и второй телефон не показывал ни анимацию, ни хитбокс.
Теперь клиент сравнивает номер `punch`: новое значение остаётся в базе и не
теряется даже при медленном соединении.

Боевой поток читает только `players.json`. Чат запрашивается отдельно и реже,
поэтому длинная история сообщений больше не увеличивает задержку движения.
Сообщения, которые уже не влезают на экран чата, клиент сам удаляет из
`rooms/<room>/chat`, чтобы узел не разрастался.
Хитбокс любого игрока рисуется одной и той же чёрной полупрозрачной полосой.

## Если онлайн не подключается

Проверь по порядку:

- создана именно Realtime Database, а не Firestore;
- URL в `config.ds` совпадает с адресом базы и начинается с `https://`;
- правила опубликованы, а не просто вставлены в редактор;
- оба устройства собраны с одним URL и именем комнаты;
- в настройках игры → **Консоль** нет `Permission denied` или HTTP 401.

Если приложение было закрыто аварийно, его слот может оставаться занятым до
шести секунд. После этого клиент считает слот устаревшим и занимает его снова.
